API overview

Nector 0.1.0 exposes a C API and move-only C++17 RAII wrappers.

Choose an entry point

Include <nector.hpp> for the complete C++ API, or include individual C headers to use only the required modules. Nector is not header-only: applications must link the implementation libraries and make shared libraries discoverable at runtime.

The C API uses opaque handles and nector_status. Every successful create or load operation that returns an owned handle has a corresponding destroy or unload function. Check status values and use nectorGetLastError() for diagnostic detail.

The C++ wrappers destroy owned handles automatically, delete copying, support moves, and translate failing status returns into nector::Error. Use Error::status() to inspect the nector::Status.

#include <nector.hpp>

int main() {
    nector::Surface surface(320, 200);
    nector::Painter painter(surface);
    painter.setFillColor({0.15F, 0.25F, 0.45F, 1.0F});
    painter.fillRectangle({0.0F, 0.0F, 320.0F, 200.0F});
    const auto pixels = surface.readPixels();
    return pixels.size() == 320U * 200U * 4U ? 0 : 1;
}

Node is a non-owning scene-node wrapper. Accessors such as Window::input(), Window::scene(), CdslPackage::scene(), and the painter in UiEvent also expose borrowed resources. Keep their owners alive for the full period of use. In particular, a Window borrows its Scene.

Link the API you use

With the packaged CMake configuration, link Nector::nector for the monolithic library. Add Nector::nector_dsl_compile when using CDSL. Modular targets are available as Nector::nector_core, Nector::nector_rasterization, Nector::nector_font, Nector::nector_image, Nector::nector_nimation, Nector::nector_input, Nector::nector_scene, Nector::nector_audio, Nector::nector_platform, and Nector::nector_interface.

See the quick start for complete integration and the DSL guide for data-package compilation and loading.
