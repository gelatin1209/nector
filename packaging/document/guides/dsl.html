What .dll-nector means

Despite its suffix, a .dll-nector file is not an operating-system dynamic library. It is not native executable code and is not VM bytecode. Do not pass it to a system library loader.

It is a Nector data container with three sections:

SectionContents
DataSerialized scene nodes and their properties.
TextSerialized actions and their operations.
EndThe terminating section used to complete and validate the package structure.

The CDSL library parses these sections and constructs a Nector scene. Use nectorCdslLoadFile, nectorCdslLoadMemory, or the corresponding CdslPackage methods rather than treating the file as a shared library.

A complete source example

Save the following as my-ui.nector. It uses the implemented window, label, button, action, property-assignment, and event-emission syntax.

window "main" {
    title = "Nector DSL UI";
    width = 480;
    height = 240;
    padding = 20;
    gap = 12;
    background = #f4f6fb;

    label "status" {
        text = "Ready";
        font_size = 24;
        foreground = #182033;
    }
    button "run" {
        text = "Run action";
        height = 44;
        on_click = "finish";
    }
}

action "finish" {
    set "status".text = "Finished";
    emit "finished", "done", 100;
}

Node event properties connect interaction to action identifiers. In this example, clicking run invokes finish, which updates the label and emits a custom event.

Compile, inspect, and view

Load the environment scripts described in the quick start, then run the compiler from the package root:

nectorc my-ui.nector my-ui.dll-nector

The actual command-line contract is:

usage: nectorc <input.nector> <output.dll-nector>

There are two required positional paths. The compiler reports invalid usage or a compilation failure and does not require a system DLL suffix on the output.

Validate the container without opening a window, or inspect its static binary structure:

ndvwr --check my-ui.dll-nector
nddbg my-ui.dll-nector
nddbg -d my-ui.dll-nector > decompiled.nector
nddbg -s my-ui.dll-nector
nddbg -t my-ui.dll-nector
nddbg -d -s -t --records --hex my-ui.dll-nector
nddbg --all my-ui.dll-nector

ndvwr --check <ui.dll-nector> reports whether the package is valid. The default nddbg report includes the summary and hexadecimal bytes with ASCII. -d decompiles the data package back to .nector DSL and emits pure DSL when used alone; -s lists node and action symbols; -t lists structure ranges. Options can be combined, and --all enables every view. Every nddbg option accepts one or two leading dashes, such as -d/--d, -records/--records, and -help/--help. Errors use an error: prefix; supporting consoles show the prefix in red and the message in white, while redirected output remains plain text without escape sequences. Addresses are absolute file offsets, not process memory addresses. Structure ranges use 0xSTART-0xEND with an exclusive END. Neither validation nor inspection loads a scene, creates a window, or executes actions.

Open a valid result with the bundled viewer:

ndvwr my-ui.dll-nector
ndvwr my-ui.dll-nector path/to/font.otf

Its viewing contract is ndvwr <ui.dll-nector> [font-file]. Without the optional font argument, it checks NECTOR_FONT and then the package's default DejaVu Sans asset.

Use a package from C++

#include <nector.hpp>

int main() {
    auto package = nector::CdslPackage::load("my-ui.dll-nector");
    if (package.hasAction("finish")) {
        package.call("finish");
    }
    auto scene = package.scene();
    auto status = scene.findNode("status");
}

CdslPackage::compileText returns owned byte storage as a std::vector; CdslPackage::compileFile writes an output file directly. loadMemory loads bytes already held by the application. Actions can be queried with hasAction, actionCount, and actionId.

The scene returned by CdslPackage::scene() is borrowed, so keep the package alive while using the scene or its nodes. C applications use nectorCdslFreeBuffer for memory returned by nectorCdslCompileText, and nectorCdslDestroyPackage for loaded packages.

See the API overview and dsl_comp.h for the complete declarations.
